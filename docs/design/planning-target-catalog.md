# Planning Target Catalog — Shared Contract

Proposed/frozen-before-consumers P02 interface at base23ef525. Concrete strict, frozen, extra-forbidden schemas are in `app/planning_catalog/contracts.py`. Root reviews this interface before service/UI integration. No route/runtime/provider call is installed by the contract commit.

`POST /api/customer/v1/workspaces/{workspace_id}/planning/target-catalog` accepts `TargetCatalogIntentV1`: an owned account ID plus explicit starts_at/ends_at reporting window. Server rejects future end, empty/reversed or greater-than366-day windows using the existing diagnostic validator. This reporting window is not the future planning budget period. The request cannot supply a provider, source generation, target object, mandate, qualification or authorization result.

Output `TargetCatalogV1` identifies workspace/account/connection/platform and connection_version (the existing source-generation binding, not a new invented numeric epoch), exact source-binding and inventory digests, currency/timezone, reporting window, read start/end and existing source expiry. Per-kind coverage is mandatory for campaign plus adset (Meta) or adgroup (Google/TikTok), with observed count, explicit complete/partial/unavailable status, bounded scope and reasons. No paginated or capacity-truncated collection is advertised complete. Collector failures remain unavailable; no successful empty list substitutes for missing reads.

Each target has an opaque selection key, parent key, nullable observed budget-owner key, nullable native name with provenance, provider-discriminated current settings, unavailable fields and reasons. Keys are identifiers only: future consumers must freshly re-resolve exact owned source and current observation. No caller can turn a key or hash into authorization. Raw native IDs, credentials and execution qualification fields are not projected. The whole response declares advertising_writes_enabled:false, spending_authority:none and atomic_snapshot:false.

Reuse mandate-free `NativeDiagnosticService.read(AccountDiagnosticRequest)` and all three existing AccountObservationRequestV2 adapters. Preserve original-session/provider authority, paid_work, tenant/account/connection binding, source generation, read-control gates, bounded scoped credentials and post-IO reauthorization/rebinding/time checks. API transactions are released before native IO. Do not use qualified optimization target catalogs or financial source/mandate runtime assembly. The existing helper type named ExecutionAccount is only a source-ownership tuple here; no execution permission is imported from it.

Initial projection faithfully exposes current inventory coverage: Google campaigns/budgets, Meta campaigns/adsets with known-status limitation, TikTok campaigns/adgroups with regular-family limitation. Missing names stay null. Google's uncollected adgroups explicitly report unavailable/not_collected, not empty-complete; completing their bounded read remains P02 follow-up, not a removal of Google scope. All three providers have catalog support from the first service package. Shared Google budgets remain visible and linked by budget-owner key; do not apply executor eligibility filters. An unknown budget owner stays null rather than fabricated from an incomplete hierarchy. Native Meta/TikTok amounts retain existing unqualified native-unit semantics; no USD/micros conversion is assumed. Google inventory's unrelated billing incompleteness must not block advertising-target projection when its advertising read succeeded.

Row bound is200 per kind and400 per response; existing collectors' page/time/byte bounds remain unchanged. No silent truncation is introduced. Inventory projection adds no persistent table, execution approval, reservation or worker. Planning consent0086 belongs to the separate initial_start lane; this module does not change its API/router or schema.

Service acceptance after root review: real mocked HTTP inventories for all three providers; parent/account/settings fidelity; shared-budget visibility; missing names and incomplete scope accurately shown; no financial runtime required; source/account/session changes during IO rejected; foreign workspace and revoked session rejected; inactive entitlement/read control preserved; strict response excludes raw secrets/IDs and additional fields; mutation sinks remain denied. No live provider calls. This catalog is a prerequisite for manual scenarios/briefs, not comprehensive plan completion.
