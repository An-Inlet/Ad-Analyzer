## Reconnect Is A Different Lifecycle Boundary

The frozen Q11 reconnect alternative cannot currently be assumed to preserve V1.
At `app/google_connections/service.py:239–249`, reselecting an existing connection
calls `bump_workspace_export_revision` before incrementing its generation.
`app/lifecycle/privacy.py:35–59` defines that operation as semantic erasure and
calls `erase_workspace_plans`. The latter (`app/planning_documents/invalidation.py:21–46`)
deletes plan versions, inputs, events, request records and catalog lineage.
Thus a genuine reconnect currently removes the old plan/decision graph; it does
not merely make an existing plan historical for a V2 successor. This is a concrete
source-level acceptance mismatch, not a newly reproduced runtime failure.

Do not substitute direct generation changes, counter-only invalidation or synthetic
retained rows to claim reconnect acceptance. Do not weaken approved privacy
invalidation to satisfy the Q11 wording. A separate reviewed reconnect acceptance
must distinguish erasure/no-resurrection from history-preserving reporting
correction, or explicitly reconcile the lifecycle contract before any behavioral
change. The proposed V5 correction slice does not depend on that decision.
