# Configured reported-rule runtime

This is the original-session operational reported-efficiency path approved in
`reported-rule-candidate-interfaces.md`. It is a separate evidence and policy
family; it does not register reported comparisons as qualified learning.

The ordinary customer candidate API and session-automation API load an explicitly
pinned `ReportedRuleAssemblyManifestV1` and `ReportedRulePolicyBundleV1`. The bundle
contains all numerical rule parameters and, for `session_automatic`, the distinct
Start policy, cadence and lifetime. The manifest pins the existing optimization
manifest. `RegisteredReportedRuleSource` identifies the implemented owned DB
comparison reader. It has no arbitrary evidence callback. The process registry
still returns `None` by default; neither a file nor a descriptor supplies financial
qualification. Legacy configuration and wire discriminators remain unchanged.

`configured_session_automation(db, principal, identity, configuration)` binds the
actual request principal and existing configured native optimization runtime.
Its selection factory receives the exact persisted mandate binding so catalog
periods are never inferred or replaced with a generic current interval.
`run_configured_session_automation(engine, configuration, limit=10)` reconstructs
that assembly separately for each stored original session. It releases its
admission session locks before invoking the worker. The normal customer tick uses
this assembly only when the existing opt-in automation flag is enabled. A disabled
master switch returns before loading policy or constructing native factories.

The bounded runner selects at most one due run per workspace per tick. Invalid
original authority or an unavailable factory defers that exact run so it cannot
shadow a later current session. This maintenance cannot create provider claims,
change fences, release reservations, or adopt the former session's comparison.
Existing worker checks, semantic epoch admission, candidate dependency retraction,
protected review guards and exact reservation replacement remain authoritative.
