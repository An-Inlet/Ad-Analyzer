## Candidate with a demonstrable same-call boundary

A concrete pure duplication exists in `selected_storage.historical_capture`: each already-parsed fact calls `fact_values(fact,wid,aid)` twice in one equality expression, once for expected values and again merely for dictionary keys. Each call serializes canonicalJSON and hashes it. The same function calls `capture_values(value)` twice in another equality expression; each invokes selected_capture_digest, which fully revalidates the graph and canonicalizes it. There is no SQL, callback, clock or external authority boundary between these paired calls. A private local expected-values variable can retain the first result for the exact same comparison, preserving all public validation and both later SQL dependency reads. `_selection` has the same values-for-values/keys pattern.

This is a source-proven redundant computation, not a measured promise of sufficient margin. On a61-day capture the fact duplication scales with returned facts and recurs at each independently required graph read. It is preferable to removing fresh proofs or adding generic prepared-graph trust. A coherent first contract could cover only these three same-expression duplicate computations in selected_storage, with no change to public helper signatures, source reads, row ordering, capacity limits, exception conversion or lock order. Preserve original evaluation order and first exception; obtain expected keys only from the exact returned dict. Do not extend to serializer/canonical shortcuts or cache across reads.

Required review before any implementation: verify calls are deterministic concrete local functions with no subclass callback behavior that the removed second call intentionally exposes; preserve public unsupported/copied-model behavior. Required bounded tests: prechange canonical/scalar values and exact corrupt-present errors, fact/header/selection copied negatives, real current/historical capture equality on both DBs, mutation between independent proof reads still rejected, callback/transaction replacement and no-write behavior unchanged. A counting spy may prove one local serialization result per comparison, but cannot replace real graph validators. No full acceptance rerun is implied here.
