Source-only follow-up to f9e873c and the measured assertion inventory. Production remains unchanged. These cases test the installed validator behavior before choosing a private checked-kernel implementation; they are not performance evidence. No test body or application import has run for this package.

## Bounded pure selection

New file: `tests/test_selected_ticket_characterization.py`, proposed sixteen nodes only:

1. Three parameterized genuine synthetic fixture baselines: selected ready, paired ready, and V6 owner ready.reporting. Each invokes the current public assertion, repeats mandatory declared validation and assertion, and checks exact JSON/digest stability. These are real domain constructors but not actual acquired/SQL-authorized evidence.
2. Two top-level selected/paired subclass cases: a custom after-validator sentinel and an overridden public assertion remain observable on the current public path. This establishes why future dispatch must preserve the entire original sequence for nonexact roots, not just validate them as a base.
3. Three nested declared-always subtype cases: planning AccountRef, catalog ProviderReferenceV1, and presence CountCellV1. Each subtype has a custom validator/serializer and extra field; embed it through an actual declared parent field, validate that parent normally, assert the returned child is the exact declared base, and preserve its original base JSON. Record callback behavior explicitly rather than assuming outer configuration propagates.
4. Two legacy edge cases: ConfirmedGoalRef.definition and CommerceEvidence.document, with GoalDefinition/GoalSalesProgressV1 subtypes and nested MeasurementWindow subtype. A custom wrap serializer preserves the valid base payload while recording its invocation. Mandatory outer validation must invoke the original serializer, produce exact declared base children, retain full digest binding and then produce stable bytes on a second parse. An invalid custom serialized payload must still fail at the same original boundary (within each case).
5. Four datetime variants through actual ReportingWindow fields: exact datetime with UTC, exact datetime with a fixed timezone offset, exact datetime with ZoneInfo across a DST fold, and exact datetime with a custom tzinfo. Assert original instants/fold/serialized bytes and inspect resident returned types. The custom object case proves whether custom behavior survives; it must not be described as canonical inert time. It is not a simulated authority clock.
6. Two copied-invalid graph cases: a copied boolean integer field in a source/account and a copied invalid selected capture count. Current mandatory validation/assertion must reject, with no kernel implementation involved.

The three genuine fixtures use `tests.test_selected_plan_bundle.ready`, `tests.test_selected_paired_composer.ready`, and `tests.owner_review_v6_fixture.ready`. Commerce uses existing `tests.test_planning_document_ports.ready_bundle/commerce_data`; no fixtures or shared helpers change. Class field/configuration inventory can be frozen in tests after these characterizations; an AST list alone does not prove runtime behavior.

## Small eligibility boundary proposed for review

No eighty-class runtime schema registry. Keep original mandatory declared validation at entry. Use only the resulting canonical models in a private invariant body, in the same synchronous call before any SQL or callback boundary. An exact top-level type check selects the original path for subclasses. All original after-SQL assertions remain public and mandatory.

A possible conservative scalar eligibility check reads resident declared-field values from each returned model's `__dict__`, and traverses tuple values. It does not serialize, call properties, compare/hash arbitrary values, invoke timezone methods, or access principal/callback objects. Standard allowed leaf types must be exact: str/int/bool/None, Decimal, date, and datetime. Exact datetime additionally needs resident `tzinfo` whose type is exact `datetime.timezone` or exact `zoneinfo.ZoneInfo`; a datetime subclass or custom tzinfo selects the original sequence. If the returned graph contains any unexpected container/scalar, it also selects the original sequence. Type inspection precedes equality/hash or custom attribute access. A missing field, cycle, or unexpected model/container shape must not be interpreted as trust.

This is a custom-behavior exclusion check, not validation, serialization, source/currentness proof, or a reusable prepared token. It must not replace mandatory model validation or create a public bypass flag. Reading exact datetime.tzinfo is the built-in descriptor only; no `utcoffset`, `repr` or serialization is performed by eligibility. State is local to one invocation; no cross-call/cache state.

Avoid arbitrary model subclass attribute hooks during scanning; use object.__getattribute__ for resident dictionaries. Normally validated declared children are expected to be exact base models, but legacy behavior must be demonstrated first. If the named legacy cases retain custom children, require a narrow original fallback rather than silently widening the scanner. The fallback executes the ORIGINAL REMAINING SUFFIX, never restarts the common prefix. Reader: retain original ticket validation then declared bundle validation once; after eligibility, fallback calls the original bundle.assert_ticket(ticket). Public paired: retain original type(self) validation then ticket validation once; at the original nested selected.assert_ticket call, fallback invokes that original method. Preserve original versus returned locals exactly. A reader declared parse may already downcast a subtype, unlike public type(self) validation; do not impose new subtype behavior. Trace assertions fit inside the sixteen cases. This ordering is independently reviewed; concrete production implementation remains gated on characterization.

## Execution and decision

Prepare source, obtain independent preflight, then resource-guarded static checks and exact sixteen-node collection/manifest only under the parent's slot authorization. Bodies require separate one-run authorization. Preserve the first unexpected result, including an invalid hypothesis; do not weaken production to make characterization pass. No SQL, provider, observer, authority delay, actual API or retry belongs to this selection.

A successful characterization supports a small four-production-file design, not automatic implementation or claimed timing margin. Scanner cost and any remaining semantics must be candidly assessed before repair. The measured 0.685 seconds is the entire assertion budget, not an expected saving, and historical authority failures remain open.
