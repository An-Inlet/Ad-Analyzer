# Configured Meta Image Execution Assembly

This additive bundle uses the ordinary customer execution and social configuration
APIs. It does not install a live evidence source or resolve Meta qualification gaps.
Google's manifest, plan/profile serialization and configured execution path remain
compatible. TikTok runtime assembly remains unavailable.

`production_runtime.provider_composition.configured_execution(db, principal,
provider, settings, media_store_factory, *, social_only=False)` is a request-owned
context manager. It admits descriptors without building readers, then lazily enters
only the provider selected by a typed plan, catalog request or original activation
request. Generic run/receipt routes therefore do not infer provider from URLs.
The social-only URL hint preserves default unavailable behavior but is not the
security boundary: all typed context, catalog and economic dispatches reject TikTok
before source construction or IO. Its inert HTTP slot also denies independently.

Absent Meta manifest/source leaves Google available. Configured Google and Meta
manifests must agree on environment; mismatch fails before reader construction.
The shared capability response uses the actual admitted catalog configuration,
not inert adapter fields. Individual activation-enabled flags are checked again
when reading exposure or obtaining that provider's activation context.

Meta configuration uses these nonsecret server settings:

- `AD_ANALYZER_META_EXECUTION_MANIFEST_PATH`
- `AD_ANALYZER_META_EXECUTION_MANIFEST_DIGEST`
- `AD_ANALYZER_META_EXECUTION_BUNDLE_PATH`

The immutable manifest transitively pins the bundle. Every profile/rule input is
explicit, USD exponent2 is the initial supported mapping, and personal-DSA capture
is unsupported. The actual customer still answers and confirms exact declarations;
no factory supplies unconditional answers. Existing SocialPlanProducer and owned
configuration-review services produce the executable plan with its durable exact
configuration approval reference.

Owned Meta contexts open credentials from the current account/integration/generation
vault through short private sessions bound to the actual request engine and original
customer session. Tokens expiring within the configured margin require reconnect;
this assembly does not renew them. Catalog IO runs outside those locks and then
reauthorizes scope/generation. Private media access verifies the original owned
binding and repeats authorization after storage IO. Contexts and transports close
on success and failure. No global user/token/session cache is introduced.

The real HTTP factory refuses contract-test manifests before HTTPTransport creation.
Synthetic financial scenarios require an explicit MockTransport replacement. Source
registration is trusted Python construction, never client proof JSON or configurable
imports. Descriptors do not prove financial bounds. Existing qualification readers,
PortfolioExposureReader, exact approval, original parent holds and unknown outcome
fences remain authoritative. Activation remains a separate reviewed status change.

All four native Meta catalog blockers remain unchanged. Live creation with any
blocker is rejected before configuration evidence admission; source IDs or fixture
qualification results cannot remove them. This package's configured API evidence
is contract-test only. A real qualification source plus a separately reviewed way
to resolve exact native catalog facts is still needed before live Meta admission.

The configured fixture `tests/meta_runtime_fixture.py:configured_meta_customer`
provides actual owned Meta credentials, approved B14 image and private local media,
explicit contract-test configuration/economic readers, and actual injectable HTTP
responses. It seeds no execution review, attempt, receipt or reservation and does
not override runtime getters. Tests create mandate consent, opaque configuration
selection, explicit declaration confirmation, exact creation review, paused graph,
separate activation approval and status readback through the ordinary APIs.

The Google real-transport admission regression now exercises configuration discovery,
the first typed provider IO boundary. Local mandate preparation is intentionally lazy
and no longer opens an unused transport. Its no-real-constructor/no-provider-IO
assertion is preserved. Legacy explicit injected runtimes remain supported.

Process-local pinned configuration requires coherent deployment and draining old
workers; distributed hot-reload or global policy revocation is not claimed. Actual
Meta TLS acceptance is a dependent package after this backend freeze.
