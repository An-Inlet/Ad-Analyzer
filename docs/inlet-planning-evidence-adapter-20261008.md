# Trusted Planning Evidence Adapter

Branch `codex/inlet-planning-evidence-adapter`, worktree `/workspace/inlet-planning-evidence-adapter`, base35e2a3b (reviewed native target UI and repaired planning ports). Shared direction and final local callback were reviewed in proposal85690cc/c5dec7c; persistence lane confirmed the source fence convention and callback signature. No ports/model/migration/collector changes.

`OwnedPlanningEvidenceReader` collects actual owned catalogV2 through NativeDiagnosticService, wraps current CampaignPerformanceV1/V2 read from exact owned native campaign mappings/completion/manifests, and reads actual confirmed Shopify goal progress. The original principal/session is fixed; transaction scopes end before native HTTP. All three providers use existing concrete read clients. Generic HTTP/metadata/source failures propagate and abort, never become a data gap. Known absent current completion, absent campaign mapping and different current reporting windows remain explicit gaps. A real catalog deadline bounds the derived operation references; no new source lifetime is invented.

Google aggregate conversions and zero/defaulted Meta conversions remain unqualified; only positive Meta selected-event reporting may be reported-only, never causal or cross-platform-comparable. TikTok generic counts do not become goal conversions/value/CPA/ROAS. Empty campaign rows remain null. Current-only imports cannot provide arbitrary historical/comparison aggregates; the adapter does not slice, relabel, invent or replay old measurement documents. Unsupported >366-day native windows cannot produce a qualified generation without real catalog evidence. Commerce without a reproducible prefix fails closed except explicitly known missing-history/no-closed-day states with a positively owned store and exact source pins; not-started goals retain their explicit state. Missing history never becomes observed zero. These limitations remain visible rather than claiming complete campaign performance or comprehensive plan readiness.

`resolve_source_fences` is shared with persistence: source_binding_digest uses the existing planning-source.v1 scope digest and source_revision is the exact connection_version. `recheck_local_sources` performs only local database work within the caller transaction, after caller authority locks: original session/owner, goal confirmation/definition, current source/privacy fences, catalog money context/expiry, exact performance pointer/native mapping/recomputed manifest/document, and commerce source revision/watermark/import/current measurement/prefix/retention. It rechecks billing and session at final time. It never invokes provider identity callbacks or commits. Persistence must keep its own final authority-age/time check and atomic insert after this callback. Collection performs its last provider identity check before this final local source/time validation.

Tests use actual concrete native MockHTTP readers, persisted owned campaign metrics/completion manifests, and the existing real Shopify normalization/import plus confirmed-goal fixture. They do not manufacture ready EvidenceBundle values. No provider calls or execution capability bypass is used. Initial fixture failures were missing required Google/TikTok window columns and an adverse mutation selecting a preexisting unrelated campaign; fixes supplied required columns and scoped the mutation to the collected performance campaign. No production guard was weakened.

Qualification evidence and independent review status are recorded below when terminal. No hosted, live-provider, production, merge or deployment verification is claimed.
