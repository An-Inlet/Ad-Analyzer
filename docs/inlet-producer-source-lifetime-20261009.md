# Genuine Producer Source Lifetime Qualification

Implemented on `codex/inlet-producer-source-lifetime`, base `74ffc9d` plus reviewed
reported composition dependency `bc5de9f` (local cherry-pick `4678013`). This is
bounded fixture capacity work, not an aggregate regression or product qualification.

## Change And Boundaries

The scripts-owned `SourceLifetime` utility binds 16 closed profile names to 11
explicit helper files, literal source commits, exact Git trees and fixed drivers.
It validates immutable source bytes before child launch and before deletion,
records bounded sibling provenance, and removes only its newly owned source/archive
after confirmed process reap. Unknown files/directories, symlinks, modified source,
unconfirmed completion and pre-deletion provenance failures retain source. Ordinary
runner exceptions retain source even when the runner may already have reaped it.
Social two-phase source survives parent DDL and is removed only after `stop_child`
returns. Native restore mode keeps its previous TemporaryDirectory lifetime; only
its fixture mode uses this utility. A failure writing the final post-deletion
record cannot restore deleted reproducible bytes and is surfaced, not reported as
successful provenance completion.

IDs, logs, XML, SQLite and media stay outside the deleted source. Generic runners,
extractors, original W1 artifacts and all five historical batches (293 nodes) are
unchanged. No retrospective cleanup or source sharing is introduced. The newly
added TikTok draft and optimization source helpers are intentionally excluded and
need a separately reviewed two-profile followup before aggregate capacity claims.

`wiring-audit.json` proves the generic snapshot/budget snapshot/historical harness
files unchanged. It also compares the reported fixture to frozen `bc5de9f`: exact
signature/defaults, other functions/classes, and contextmanager body are unchanged
apart from the approved extraction/runner lifetime wrapper and transitions.

## Retained Evidence And Limits

`provenance-validation.json` checks 18 actual representative/exception provenance
records: every source is absent, each record says removed, and every fixed driver
hash matches its current source. Their inventories total 282,319,768 logical bytes
removed, not filesystem free-space accounting. Seven actual profile types appear:
budget_preparation_0079, candidate_dual, configured_draft, reported_original,
reported_restore, restore_fixture and social_configuration. Sibling names and
per-source counts/hashes are retained in that external proof; other allowlisted
profiles have reviewed wiring, not a claimed new actual positive qualification.

This bounds normal repeated extraction growth. It does not establish sufficient
space for all SQLite/media/browser artifacts or for deliberately retained abnormal
sources. No live providers, advertising writes, remote operations or original W1
source/database changes occurred.
